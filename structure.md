# Peta Struktur Proyek

Boilerplate company profile berbasis Next.js (App Router, TypeScript, Tailwind). Perbarui file ini setiap kali ada file atau folder yang ditambah, diganti nama, atau dipindah.

## Akar proyek

| Path | Tanggung jawab |
|---|---|
| `CLAUDE.md` | Aturan untuk AI, mengimpor `docs/rules/*.md` |
| `structure.md` | Peta struktur proyek ini |
| `AGENTS.md` | Catatan agen bawaan Next.js |
| `README.md` | Pengantar proyek bawaan scaffold, ditambah bagian "Deploy" (nilai `SITE_URL`, `SITE_INDEXING`, `DATA_SOURCE` harus diatur saat build) |
| `.env.example` | Contoh variabel lingkungan (`DATA_SOURCE`, `SITE_URL`, `SITE_INDEXING`) |
| `.claude/launch.json` | Konfigurasi pratinjau dev `company-profile-dev`: menjalankan `npm run dev` di port 3000 (nilai bawaan aplikasi berlaku: `DATA_SOURCE=demo`, `SITE_INDEXING` mati) |
| `vitest.config.mts` | Konfigurasi Vitest: tes ada di `tests/**/*.test.{ts,tsx}`, JSX otomatis lewat `oxc`, dan `tests/setup/next-mocks.ts` dijalankan sebelum setiap file tes |
| `next.config.ts`, `tsconfig.json`, `eslint.config.mjs` | Konfigurasi Next.js, TypeScript, dan ESLint. `next.config.ts` mengaktifkan `cacheComponents`, `partialPrefetching`, aturan turbopack untuk CSS, dan `headers()` yang menerapkan `buildSecurityHeaders()` ke `source: "/(.*)"` (semua rute, termasuk gambar OG dan file teknis) |
| `THEME.md` (menyusul) | Panduan membuat tema baru dari desain |
| `UPDATING.md` (menyusul) | Cara menarik pembaruan boilerplate ke tema |

| `src/app/` | Rute Next.js. Karena itu slug dan halaman yang tidak ada di `/layanan`, `/portofolio`, dan `/artikel` sudah ditolak lebih dulu oleh `src/proxy.ts` dan ditulis ulang ke `/_tidak-ditemukan` (tidak cocok rute mana pun), sehingga yang dilayani adalah `not-found.tsx` akar ini dengan HTML lengkap dan status 404 |
| `src/app/(site)/` | Website publik. Saat ini berisi `layout.tsx` (async: membangun `SiteContext` lewat `getSiteQueries()`, `getSiteEnv()`, dan `getSiteContext`, lalu merender JSON-LD Organization dan WebSite serta `SiteShell`) dan `template.tsx` yang membungkus setiap rute dengan `RouteGuard`. Seksi bertingkat juga punya `template.tsx` yang sama: `artikel/template.tsx`, `artikel/halaman/template.tsx` (paginasi `/artikel/halaman/[n]`), `layanan/template.tsx`, dan `portofolio/template.tsx`, karena Next.js menyembunyikan rute lama per tingkat segmen sehingga setiap tingkat yang anaknya berganti butuh penjaganya sendiri. Batas untuk pergantian antar-anak di setiap tingkat ada di `RouteGuard`. Halaman yang sudah ada: `(home)/page.tsx` (beranda), `tentang/page.tsx`, `kontak/page.tsx`, `privasi/page.tsx`, `syarat-ketentuan/page.tsx`, dan `kebijakan-editorial/page.tsx`. Ketiga halaman hukum masing-masing memanggil `getLegalPageModel` dengan slug tetapnya dan memanggil `notFound()` bila modelnya `null`. Halaman layanan, portofolio, dan artikel: `layanan/(index)/page.tsx`, `layanan/[slug]/page.tsx`, `portofolio/(index)/page.tsx`, `portofolio/[slug]/page.tsx`, `artikel/(index)/page.tsx`, `artikel/halaman/[n]/page.tsx`, dan `artikel/[slug]/page.tsx`. Pola sama (model, `notFound()` bila `null`, `generateMetadata`, `JsonLd`, `Breadcrumbs` di dalam `Container`, view), dengan tambahan: rute daftar yang modulnya mati menghasilkan 404 asli. Rute dinamis menerima `params` sebagai `Promise` dan mengekspor `ensureStatic = "navigation"` (Next.js 16.4, hanya butuh Cache Components): seluruh keluaran rute harus statis, slug atau `n` yang tidak dikembalikan `generateStaticParams` dirender penuh lebih dulu (render statis memblokir, tidak ada shell cadangan yang dilayani), dan pada build produksi `notFound()` di dalamnya terjadi saat prarender sehingga statusnya 404. Di dev setiap permintaan dirender per permintaan, dan batas `<Suspense>` di atas halaman (`loading.tsx` milik halaman itu sendiri dan batas di `RouteGuard`) membuat shell terkirim dengan status 200 sebelum `notFound()` berjalan. Status 404 yang pasti di dev maupun produksi datang dari `src/proxy.ts`, yang memeriksa slug sebelum render dimulai; `notFound()` di halaman tetap ada sebagai penjaga kedua.
