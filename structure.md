# Peta Struktur Proyek

Boilerplate company profile berbasis Next.js (App Router, TypeScript, Tailwind). Perbarui file ini setiap kali ada file atau folder yang ditambah, diganti nama, atau dipindah.

## Akar proyek

| Path | Tanggung jawab |
|---|---|
| `CLAUDE.md` | Aturan untuk AI, mengimpor `docs/rules/*.md`, dan merujuk `THEME.md` serta `UPDATING.md` |
| `structure.md` | Peta struktur proyek ini |
| `AGENTS.md` | Catatan agen bawaan Next.js |
| `README.md` | Pengantar boilerplate (memulai, tabel skrip npm, rujukan dokumen), ditambah bagian "Deploy" (nilai `SITE_URL`, `SITE_INDEXING`, `DATA_SOURCE` harus diatur saat build) |
| `.env.example` | Contoh variabel lingkungan (`DATA_SOURCE`, `SITE_URL`, `SITE_INDEXING`) (kini juga `SUPABASE_URL`, `SUPABASE_PUBLISHABLE_KEY`, `SUPABASE_SECRET_KEY`, `SUPABASE_DB_URL`, dan `CONTACT_IP_SALT`, dibiarkan kosong; `.gitignore` mengabaikan `supabase/seed.sql` dan `supabase/.temp/`) |
| `.claude/launch.json` | Konfigurasi pratinjau dev `company-profile-dev`: menjalankan `npm run dev` di port 3000 (nilai bawaan aplikasi berlaku: `DATA_SOURCE=demo`, `SITE_INDEXING` mati) Entri kedua `company-profile-supabase`: `sh -c "DATA_SOURCE=supabase npm run dev -- --port 3002"` di port 3002 (variabel dari shell menang atas `.env.local`), membutuhkan `.env.local` berisi env Supabase |
| `vitest.config.mts` | Konfigurasi Vitest: tes ada di `tests/**/*.test.{ts,tsx}`, JSX otomatis lewat `oxc`, dan `tests/setup/next-mocks.ts` dijalankan sebelum setiap file tes (kini dua project: `node` untuk semua `tests/**/*.test.{ts,tsx}` kecuali `*.dom.test.tsx`, dan `dom` dengan `jsdom` hanya untuk `tests/**/*.dom.test.tsx`; keduanya memakai alias `@` dan setup `next-mocks.ts`; tes komponen klien yang punya alur (formulir, dialog, upload) ditulis sebagai `.dom.test.tsx` dengan `@testing-library/react` dan `user-event`) |
| `next.config.ts`, `tsconfig.json`, `eslint.config.mjs` | Konfigurasi Next.js, TypeScript, dan ESLint. `next.config.ts` mengaktifkan `cacheComponents`, `partialPrefetching`, aturan turbopack untuk CSS, dan `headers()` yang menerapkan `buildSecurityHeaders()` ke `source: "/(.*)"` (semua rute, termasuk gambar OG dan file teknis) |
| `THEME.md` | Panduan membuat tema baru dari desain: sebelas langkah dari `npm run theme:new` sampai `npm run theme:check`, serta daftar folder yang boleh diubah, terkunci (`LOCKED_PATHS`), dan perlu ditinjau (`REVIEW_PATHS`) |
| `UPDATING.md` | Cara menarik pembaruan boilerplate ke tema (`git fetch upstream`, `git merge upstream/main`), penanganan konflik, dan aturan migrasi yang hanya menambah |
